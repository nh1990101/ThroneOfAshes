坐标系统真相分析
═══════════════════════════════════════════

问题发现
───────────────────────────────────────────
在 renderMapTiles() 中：
  worldY = mapPixelHeight - (tile.y + 1) * tileSize

这说明所谓的"worldY"实际上是Canvas坐标（左上角为原点）！

真实的坐标系统
───────────────────────────────────────────
1. 格子坐标系（逻辑）
   - 左下角为(0,0)
   - Y向上递增
   
2. Canvas坐标系（渲染）
   - 左上角为(0,0)
   - Y向下递增
   
3. "世界坐标"实际是Canvas坐标
   - worldToScreen不做Y轴转换
   - 因为输入已经是Canvas坐标了！

转换关系
───────────────────────────────────────────

格子 → Canvas "世界坐标" → 屏幕坐标
  |                            |
  gridToWorld()         worldToScreen()
  
gridToWorld应该做什么？
  - 输入：格子坐标(gridX, gridY) - 左下角原点
  - 输出：Canvas坐标 - 左上角原点
  - 需要Y轴反转！

当前gridToWorld的实现：
  worldX = gridX * gridWidth
  worldY = gridY * gridHeight  ← 错了！

这会导致：
  格子(0,0) → (0, 0) - 左上角 ❌ 应该在Canvas底部
  格子(0,1) → (0, 32) - 往上 ❌ 应该往Canvas上方

正确的实现应该是：
  worldX = gridX * gridWidth
  worldY = mapPixelHeight - (gridY + 1) * gridHeight
  
这样：
  格子(0,0) → (0, mapHeight-gridHeight) - Canvas底部 ✓
  格子(0,1) → (0, mapHeight-2*gridHeight) - 往Canvas上方 ✓

物体偏移的问题
───────────────────────────────────────────

当前代码（第1666行）：
  y: baseWorld.y + offsetY

baseWorld.y 是什么坐标系？
  - 如果gridToWorld返回Canvas坐标（左上角原点，Y向下）
  - offsetY是用户输入的偏移（正值希望往上）
  - 那么：Canvas Y向下，正值应该减去！

正确的应该是：
  y: baseWorld.y - offsetY  ← 注意是减号！

因为：
  - Canvas Y=0在顶部，Y越大越靠下
  - 用户offsetY=10表示"往上10像素"
  - 在Canvas中"往上"意味着Y变小
  - 所以要用减法！

总结
───────────────────────────────────────────
两个问题需要修复：

1. gridToWorld的Y坐标计算
   应该：worldY = mapPixelHeight - (gridY + 1) * gridHeight
   
2. 物体偏移的Y坐标应用
   应该：y: baseWorld.y - offsetY
   
   或者在屏幕坐标层面：
   finalCenterY = gridCenterScreen.y - offsetY * scale
