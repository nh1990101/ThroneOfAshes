# 地图切图策略说明

## 问题背景

原图尺寸可能不是512的整数倍（例如5000x4000px），导致切图时最后一行或一列不足512px，会产生黑边。

## 解决方案：从左下角开始切图

### 切图顺序

```
原图坐标系（Canvas，左上角为原点）:
(0,0) ────────────────→ X
  │     ┌─────┬─────┬─────┐
  │     │ 2_2 │ 3_2 │ 4_2 │  ← 顶部，可能有黑边
  │     ├─────┼─────┼─────┤
  │     │ 2_1 │ 3_1 │ 4_1 │
  │     ├─────┼─────┼─────┤
  │     │ 2_0 │ 3_0 │ 4_0 │  ← 底部，完整切图
  ↓     └─────┴─────┴─────┘
  Y

游戏世界坐标（左下角为原点）:
       ┌─────┬─────┬─────┐
  2  │ 2_2 │ 3_2 │ 4_2 │  ← 顶部，可能有黑边
       ├─────┼─────┼─────┤
  1  │ 2_1 │ 3_1 │ 4_1 │
       ├─────┼─────┼─────┤
  0  │ 2_0 │ 3_0 │ 4_0 │  ← 底部，完整切图
       └─────┴─────┴─────┘
        2     3     4
```

### 切图逻辑

1. **循环顺序**: `row` 从 0 到 rows-1（对应游戏世界从下到上）
2. **源图Y坐标**: `sourceY = img.height - (row + 1) * tileSize`
   - row=0: 切图片底部（sourceY = img.height - 512）
   - row=rows-1: 切图片顶部（sourceY = 0 或负数）

3. **特殊处理顶部黑边**:
   - 最后一行（row=rows-1）高度可能不足512px
   - 将切出的图像对齐到canvas底部（destY = tileSize - sh）
   - 黑边出现在canvas顶部

4. **文件命名**: `${col}_${row}.jpg`
   - row 直接等于 gridY（游戏世界坐标）
   - 无需反转计算

### 优势

1. ✅ **黑边位置合理**: 黑边出现在右上角（游戏世界的高处），不影响地面
2. ✅ **简化逻辑**: 文件名直接使用row，无需flippedY计算
3. ✅ **无需偏移记录**: 不需要在配置中记录偏移坐标
4. ✅ **地面完整**: 游戏世界的底部（gridY=0）始终是完整的512x512图块

### 示例

假设原图 5120x4096px，tileSize=512:
- cols = 10, rows = 8
- 最后一行 (row=7) 高度 = 4096 - 7*512 = 4096 - 3584 = 512px（完整）

假设原图 5000x4000px，tileSize=512:
- cols = 10, rows = 8
- 最后一行 (row=7) 高度 = 4000 - 7*512 = 4000 - 3584 = 416px（不足）
- 切出的图块：底部416px是图像，顶部96px是黑边

### 坐标转换一致性

渲染时的Y坐标计算：
```javascript
// tile.y 是文件名中的Y（0到rows-1）
// 需要转换为Canvas的Y坐标（从上到下）
const canvasY = this.config.mapPixelHeight - (tile.y + 1) * this.config.tileSize;
```

这样确保：
- 文件 0_0.jpg 显示在Canvas底部
- 文件 cols-1_rows-1.jpg 显示在Canvas顶部
