# 物体偏移Y坐标修复说明

## 问题描述

用户反馈：物体的偏移像素Y计算有问题
- 正值应该往上偏移
- 负值应该往下偏移

但实际表现相反！

---

## 根本原因

### 坐标系统混淆

编辑器中有两个坐标系统：

#### 1. 格子坐标系（逻辑层）
```
Y↑
 |  (0,2)  (1,2)  (2,2)
 |  (0,1)  (1,1)  (2,1)
 |  (0,0)  (1,0)  (2,0)
 └──────────────────→ X
    左下角为原点
```

#### 2. Canvas坐标系（渲染层）
```
 (0,0)  (1,0)  (2,0)
 (0,1)  (1,1)  (2,1)
 (0,2)  (1,2)  (2,2)
  ↓ Y
  
左上角为原点，Y向下
```

### 转换关系

```javascript
// gridToWorld: 格子坐标 → Canvas坐标
worldX = gridX * gridWidth
worldY = mapPixelHeight - (gridY + 1) * gridHeight
       ↑
       需要Y轴反转！
```

### 偏移的语义

用户设置偏移时的期望（Cocos坐标系语义）：
- `offsetY = 10` → 往上移动10像素
- `offsetY = -10` → 往下移动10像素

但在Canvas坐标系中：
- Y=0 在顶部
- Y增大 = 往下移动
- Y减小 = 往上移动

所以：
```javascript
// 错误的实现 ❌
y: baseWorld.y + offsetY  // offsetY=10会让物体往下（Canvas Y增大）

// 正确的实现 ✓
y: baseWorld.y - offsetY  // offsetY=10会让物体往上（Canvas Y减小）
```

## 修复内容

### 修复1：`gridToWorld()` 方法

**位置**：[mapEditor.js:1461-1473](mapEditor.js:1461)

**修改前**：
```javascript
gridToWorld(gridX, gridY) {
    return {
        x: gridX * this.config.gridWidth,
        y: gridY * this.config.gridHeight  // 错了！
    };
}
```

**修改后**：
```javascript
gridToWorld(gridX, gridY) {
    return {
        x: gridX * this.config.gridWidth,
        y: this.config.mapPixelHeight - (gridY + 1) * this.config.gridHeight
        // ↑ 添加Y轴反转
    };
}
```

### 修复2：物体偏移应用（世界坐标层）

**位置**：[mapEditor.js:1660-1667](mapEditor.js:1660)

**修改前**：
```javascript
const world = {
    x: baseWorld.x + offsetX,
    y: baseWorld.y + offsetY  // 错了！
};
```

**修改后**：
```javascript
const world = {
    x: baseWorld.x + offsetX,
    y: baseWorld.y - offsetY  // Canvas Y向下，用减法
};
```

### 修复3：物体图片偏移（屏幕坐标层）

**位置**：[mapEditor.js:1697-1700](mapEditor.js:1697)

**修改前**：
```javascript
const finalCenterX = gridCenterScreen.x + offsetX * this.scale;
const finalCenterY = gridCenterScreen.y + offsetY * this.scale;  // 错了！
```

**修改后**：
```javascript
const finalCenterX = gridCenterScreen.x + offsetX * this.scale;
const finalCenterY = gridCenterScreen.y - offsetY * this.scale;  // 用减法
```

## 验证步骤

### 准备工作

1. **刷新浏览器**（Ctrl+Shift+R 强制刷新）
2. **加载地图**
3. **添加一个测试物体**

### 测试1：正值偏移（往上）

1. 点击物体打开属性面板
2. 设置 `偏移Y: 50`
3. **预期结果**：物体向上移动50像素
4. **验证方法**：物体应该比原来的位置高

### 测试2：负值偏移（往下）

1. 设置 `偏移Y: -50`
2. **预期结果**：物体向下移动50像素
3. **验证方法**：物体应该比原来的位置低

### 测试3：零偏移（基准位置）

1. 设置 `偏移Y: 0`
2. **预期结果**：物体回到格子中心
3. **验证方法**：物体应该居中显示在格子内

### 测试4：连续调整

1. 逐步增加偏移：`0 → 10 → 20 → 30`
2. **预期结果**：物体持续往上移动
3. 逐步减少偏移：`30 → 0 → -10 → -20`
4. **预期结果**：物体先往下回到中心，再继续往下

## 理解记忆法

### Canvas坐标系 vs 用户期望

```
用户心中的坐标系（Cocos）：
  Y↑ 正值往上
  
Canvas实际坐标系：
  ↓Y 正值往下
  
所以需要"反着来"：
  用户说"往上" (+Y) → Canvas要减少Y
  用户说"往下" (-Y) → Canvas要增加Y
```

### 公式记忆

```javascript
// 记住这个关键点：
Canvas坐标 = 总高度 - Cocos坐标

// 应用偏移时：
Canvas Y - 偏移值 = 最终位置

// 或者想象成：
"往上偏移" 在Canvas里就是"Y变小"
```

## 导出到Cocos时的处理

### 保存的数据格式

```json
{
    "gridX": 5,
    "gridY": 10,
    "offsetX": 0,
    "offsetY": 20
}
```

### Cocos中的使用

```javascript
// 在Cocos Creator中创建节点
const node = new cc.Node();

// 计算最终位置（Cocos坐标系）
const worldX = gridX * gridWidth;
const worldY = gridY * gridHeight;

// 应用偏移（直接加法，因为Cocos坐标系Y向上）
node.setPosition(
    worldX + offsetX,
    worldY + offsetY  // ← 注意：Cocos里是加法！
);
```

### 为什么编辑器里用减法，Cocos里用加法？

因为：
- **编辑器**：Canvas坐标系（Y向下）→ 用减法
- **Cocos**：Cocos坐标系（Y向上）→ 用加法

偏移值 `offsetY` 的语义始终是：
- 正值 = 往上
- 负值 = 往下

只是在不同坐标系下，实现方式不同！

## 技术要点

### 1. 坐标系统一致性

编辑器内部统一使用Canvas坐标系：
- `worldToScreen` 不做Y轴转换
- `gridToWorld` 负责格子→Canvas的转换
- 物体偏移在Canvas坐标系下应用

### 2. 语义层与实现层分离

- **语义层**：用户输入 `offsetY=10` 表示"往上"
- **实现层**：Canvas中"往上"意味着Y减小
- 转换发生在应用偏移的时候

### 3. 数据导出的坐标系无关性

保存的 `offsetX/offsetY` 是纯语义值：
- 不携带坐标系信息
- 由使用方（Cocos）按自己的坐标系解释
- 确保跨平台一致性
