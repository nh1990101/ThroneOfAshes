坐标系统分析
═══════════════════════════════════════════

1. 图片坐标系（Canvas原始坐标）
   - 左上角为原点(0,0)
   - X向右增加，Y向下增加
   
2. Cocos世界坐标系（游戏中使用）
   - 左下角为原点(0,0)
   - X向右增加，Y向上增加
   
3. 格子坐标系
   - 左下角格子为(0,0)
   - X向右增加，Y向上增加

转换关系
───────────────────────────────────────────

假设：
- 地图像素尺寸：mapPixelWidth x mapPixelHeight
- 格子大小：gridWidth x gridHeight
- 格子坐标：(gridX, gridY)

格子 → 世界坐标（Cocos坐标系）
───────────────────────────────────────────
正确的公式应该是：

worldX = gridX * gridWidth
worldY = gridY * gridHeight

因为：
- 格子(0,0)对应世界坐标(0,0) - 左下角
- 格子(0,1)对应世界坐标(0,gridHeight) - 往上一格
- 格子(1,0)对应世界坐标(gridWidth,0) - 往右一格

当前错误的公式：
worldY = mapPixelHeight - (gridY + 1) * gridHeight

这个公式是在做"从上往下"的转换，不符合Cocos坐标系！

举例说明
───────────────────────────────────────────
假设地图：2048x2048像素，64x64格子，格子大小32x32像素

格子(0,0) - 左下角
  正确: worldY = 0 * 32 = 0
  错误: worldY = 2048 - (0+1)*32 = 2016 ❌

格子(0,1) - 往上一格
  正确: worldY = 1 * 32 = 32
  错误: worldY = 2048 - (1+1)*32 = 1984 ❌

格子(0,63) - 左上角
  正确: worldY = 63 * 32 = 2016
  错误: worldY = 2048 - (63+1)*32 = 0 ❌

结论
───────────────────────────────────────────
应该使用简单的线性公式：
worldX = gridX * gridWidth
worldY = gridY * gridHeight

这样才符合Cocos Creator的坐标系统！
