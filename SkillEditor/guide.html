01 /

启动与准备

说明页可以直接双击打开；真正的编辑器需要通过本地服务运行。

推荐：双击启动

打开项目里的 SkillEditor 文件夹，双击 start.bat，保持服务窗口开启。

用 Chrome 或 Edge 打开：

http://127.0.0.1:8766/ ↗

✓ 底部显示“本地已连接”，资源库出现资源。

命令行启动

在项目根目录打开 PowerShell：

node SkillEditor/server.cjs

需要 Node.js 18+，以及项目已有依赖 node_modules/jszip。

不要双击编辑器的 index.html 启动：file:// 无法读取单位 Excel 和项目资源。此限制不影响当前这份离线说明页。
端口 8766 被占用怎么办？

若已有服务正在运行，先用浏览器打开默认地址。需要另开端口时，在项目根目录执行下方命令，然后打开 http://127.0.0.1:8767/。

$env:SKILL_EDITOR_PORT = '8767'
node SkillEditor/server.cjs

浏览器草稿按地址与端口分别保存，更换端口后可通过导入 JSON 恢复配置。更新 server.cjs 后，关闭旧服务并重新启动。

03 /

做出第一个技能

练习目标：施法者攻击 → 发射特效 → 命中后受击、伤害与击退。

新建，并填写技能 ID

点击顶部 “＋ 新建”，输入 ID，例如 guide-demo-1001，点击“创建技能”。顶部可修改技能名称；ID 可在右侧“技能设置”调整。

检查：地图和轨道为空，技能 ID 已填写。新建可撤销，取消弹窗保留原技能。

放置攻击者和受击者

点击空格子，搜索单位名称、ID 或检索名，选择“攻击者 / 施法者”和图集，再点“放置单位”。重复一次，放置“受击者”。

本例使用步兵 110010 放在 (1,3)、铁甲卫 110030 放在 (4,3)。图集由单位表 animation_name 自动映射；缺失时在右侧手动选择。

检查：场景中有两个角色，角色类型分别正确。坐标按钮可显示格子 q,r。

添加施法者攻击动作

先回到 0 ms，点击攻击者，使用右侧“＋ 施法者行为”，或点击时间轴“＋ 新建轨道 → 施法者行为”。右侧选择场景单位，动作为“攻击”，设置 10 FPS，开始时间 0 ms。

检查：时间轴出现动作帧缩略图。本例攻击动作有 5 帧，第 4 帧在 300 ms。

添加特效，再为该实例添加飞行

在资源库选中特效 1004，点击“＋ 加入特效轨道”或双击资源。在右侧把“特效位置”设为施法者；“关联时间节点”选择攻击轨道，动作第几帧 = 4、额外偏移 0 ms。持续时间留空，关闭特效循环。

保持选中这条特效，点击右侧 “为选中特效添加飞行”。飞行也关联攻击第 4 帧，起点选施法者、终点选被攻击者，速度 400 px/s，两端偏移均为 0；勾选“到达终点后隐藏特效”。

检查：飞行引用的是刚创建的“特效实例”，时间轴末尾显示“飞行结束”菱形。

在飞行结束时接上三个行为

分别新建“受击者行为”“伤害节点”“强制移动”。每条右侧的“关联时间节点”都选择刚才的飞行轨道，额外偏移 0 ms。受击动作为“受击”，伤害保留“自动分摊剩余伤害”。

强制移动明确选择受击者实例，类型设为 3 · 固定移动方向，方向“右 / 东”，移动 1 格、耗时 200 ms。本例最终移动至 (5,3)。

检查：三条行为开始于同一命中时刻；调整飞行速度后一起前移或后移。

预览、检查，再保存

按 Space 播放；拖动标尺检查发射和命中时刻。查看右侧配置提示，确认图集、特效、伤害占比与关联均正确，再按 Ctrl + S 保存。

检查：底部提示“已保存 assets/remote/Res/Config/Skill/guide-demo-1001.json”。

新轨道默认从当前时间游标开始。不要依赖添加时的先后顺序决定触发时间；以右侧“开始时间”和关联设置为准。需要快速体验，可在下方下载本例并用编辑器“导入 JSON”打开。

① 施法

先播放攻击动作。第 4 帧触发特效和飞行；改变 FPS，会改变发射时刻。

固定为 10 FPS、400 px/s；技能 ID：guide-demo-1001

在编辑器点击“导入 JSON”选择下载的文件。示例包含 2 个角色、6 条轨道，采用步兵 / 铁甲卫与特效 1004。上方参数只影响本页教学演示。保存示例前可修改技能 ID。

发射 = (4 − 1) × 1000 ÷ 10 = 300 ms
命中 = 300 + 294 ÷ 400 × 1000 = 1035 ms

试一试：只把攻击改成 20 FPS，发射提前到 150 ms，命中提前到 885 ms。再把飞行速度改成 800，命中会提前到 517.5 ms。三个命中行为始终跟随飞行结束。

05 /

六类轨道详解

每条轨道只有一个行为节点和一个触发关键帧。多次伤害、多次特效请添加多条轨道。选中轨道后，可在右侧改名、启用 / 禁用、复制或删除。

01 / CASTER

施法者行为

控制攻击者的站立、攻击、移动、受击或死亡动画。

  • 明确选择“场景单位”，默认动作是攻击。
  • 每条动作独立设置 FPS；“技能设置”的默认 FPS 只影响新轨道。
  • 支持循环。非循环动作结束后回站立，死亡动作保持末帧。

params.action 保存为枚举数值：站立0、移动1、受击2、死亡3、攻击4。

02 / TARGET

受击者行为

控制被攻击者的动作，默认播放受击动画。

  • 建议与伤害节点关联到相同的命中时刻。
  • 动画本身不创建伤害，仍需添加伤害轨道。
  • 多个目标场景中，显式指定单位实例，避免自动选到第一个受击者。

同一单位同时开始多个角色动作时，轨道列表中后面的动作优先。

03 / EFFECT

播放技能特效

设置资源 ID、源 FPS、速度倍率、位置、偏移、缩放和层级。

  • 默认 24 FPS、1× 速度。非循环“持续时间”留空时按一轮动画。
  • 填写 1–120000 ms 后，到时隐藏；动画先结束则保持末帧。该时长不随 FPS 或倍率变化。
  • 开启循环时忽略已填的持续时间，关闭循环后恢复原值。
  • “是否多目标”供游戏运行时决定是否每个敌人创建一个特效；编辑器预览不会因此批量生成目标。
04 / FLIGHT

技能移动飞行

让已存在的特效实例，从起点直线匀速飞到终点。

  • 必须先选择特效实例，再添加飞行；相同特效资源的不同实例互不干扰。
  • 设置速度、起终点，以及各自独立的 X/Y 偏移；距离改变会重算耗时。
  • 起终点在触发时记录，后续目标移动不会改变已发出的轨迹。
  • “是否与目标点朝向一致”让特效朝终点旋转，素材朝右为 0°；起终点重合时保持 0°。
  • 勾选“到达终点后隐藏特效”，在飞行结束时收起特效。
05 / DAMAGE

伤害节点

在触发时刻结算一段占比；编辑器以“预览总伤害”显示数字。

  • 全部自动：2 段各 50%，3 段各约 33.33%。
  • 手动第一段 40% + 2 个自动节点：自动段各 30%。禁用轨道不计入分摊。
  • 最终占比合计应为 100%；过多或不足会出现配置提示。
  • 数字表现持续 700 ms，并计入总时长。游戏实际伤害由战斗系统结算。
06 / MOVE

强制移动

选定移动单位与类型，设置格数或目标格，以及位移耗时。

  • 1：按移动单位水平朝向的反方向移动。
  • 2：按施法者指向移动单位的向量，取最近六边形方向；缺少施法者或重合时不移动。
  • 3：固定六方向，搭配移动格数。
  • 4：全局移动到指定 q,r，不使用格数和固定方向，不绕障碍。
  • 0 ms 为瞬移，大于 0 为滑动；“选中格子”只用来找移动单位，与“目标格子”不同。
位移预览默认忽略占用，始终受 7×7 地图边界限制；可在“技能设置”改为遇到占用停步。游戏运行时会检查路径并使用“受阻回弹”参数，编辑器预览使用全局碰撞规则。回弹距离或耗时设为 0 可关闭游戏中的回弹动画。
06 /

时间、坐标与图层

用关联表达“什么时候”，减少反复对时间

触发方式如何设置改变参数之后
绝对时间关联选择“绝对毫秒时间”，填写开始时间，或水平拖动节点。不跟随其他节点。
动作帧关联拖到角色动作帧吸附，或选择源动作并填写相对帧号与偏移。随源动作开始时间和 FPS 重算。
飞行结束关联拖到“飞行结束”菱形，或选择飞行作为关联源，并填写偏移。随飞行开始时间、速度和起终点重算。
触发时间 = 源动作开始时间 + (相对帧号 − 1) × 1000 / FPS + 额外偏移

帧号从 1 开始，指当前动作的相对帧。动作在 200 ms 开始，10 FPS 的第 4 帧在 500 ms。这与图集的绝对帧编号不同：站立 0–5、移动 6–8、受击 9–10、死亡 11–13、攻击从 14 到末帧。

拖动时开启“吸附”；按住 Alt 可临时跳过。需要解除关联时，在右侧选“绝对毫秒时间”，当前计算时刻会保留。删除关联来源时，后续行为保留最后计算出的绝对时间；删除特效实例也会删除引用它的飞行轨道。不要互相引用形成循环。

流程时长：按行为播放完成来结束

点击播放工具栏的总时长，打开“技能设置 → 流程时长”。

  • 自动：取所有启用节点“实际开始时间 + 播放时长”的最大值；空技能或全部禁用时为 0。
  • 手动：填写最小时长；节点结束得更晚时，仍会延长到完整播完。手动时长不会截断节点。
  • 循环动画按一轮参与时长计算；工具栏“循环播放”控制整个技能重复预览，两者独立。
  • 时间尺保留空白编辑区域，不代表流程至少 3 秒。最后一个伤害在 1000 ms 触发，流程至少到 1700 ms。

格子位置与像素偏移

左下角为 (0,0)，q 向右、r 向上，范围均为 0–6，奇数行右移半格。
自定义像素坐标可相对施法者、受击者或地图中心；X 向右、Y 向上。飞行两端偏移按世界方向叠加，不随角色朝向翻转。

单位按素材原始中心锚点对齐格子，受击者默认左右镜像并保持正立。场景中的特效实例可直接拖动调整偏移。

自动图层

选择“合适图层（按 Y 排序）”时，屏幕更下方的对象显示在前；同 Y 时攻击方在受击方前。必要时使用“最上层 / 最下层”覆盖排序。

07 /

保存、导入与草稿恢复

保存 JSON = 写入项目

点击顶部“保存 JSON”或按 Ctrl + S，文件由本地服务保存到：

assets/remote/Res/Config/Skill/技能ID.json

ID 为 1001 时，文件为 1001.json。同 ID 再次保存会更新同一文件。需要副本时先改技能 ID。名称不决定文件名。

技能 ID 必填，最长 100 字符，不含文件名禁用字符、首尾空白、末尾点或系统保留名称。

导入 JSON = 还原完整编排

点击“导入 JSON”，选择本编辑器格式的文件（最多 5 MB）。场景单位、图集映射、节点参数和时间关联一起还原。

导入会替换当前编辑内容，可在当前会话中撤销。重要修改先保存。

格式标识为 RPGCore.SkillPresentation，schemaVersion: 1；其他配置格式不能直接导入。

自动草稿与撤销

编辑自动保存到当前浏览器、当前站点和端口的 localStorage，刷新后恢复。它与项目中的 JSON 文件相互独立；更换浏览器或端口、清除站点数据后，不会自动带走原草稿。

新建、导入、删除和参数修改支持撤销 / 重做，历史最多 80 步，只保留在当前页面会话。正式保留配置请使用“保存 JSON”。

给开发者：导出的数据如何理解？

原始编辑数据包括 settings、scene、resourceMappings、tracks。每条轨道保存 type、enabled、startMs、binding 与 params。

// 动作第4帧触发
"binding": { "trackId": "攻击轨道ID", "frame": 4, "offsetMs": 0 }

// 飞行结束触发
"binding": { "trackId": "飞行轨道ID", "anchor": "end", "offsetMs": 0 }

resolved 记录最终时长、计算后的各节点时间 / 时长及伤害占比。导入时以原始参数为准并重新计算，不把过期的 resolved 当作编辑数据。scene.coordinateOrigin 为 bottom-left。旧动作字符串和旧坐标配置在导入时兼容转换。运行时接入细节见同目录 README.md。

09 /

常见问题

资源连接失败、角色不显示，怎么排查？

先确认使用 http://127.0.0.1:8766/ 且本地服务仍在运行。点击资源库 ↻，再打开底部“本地项目资源 → 详情”。检查 Excel 路径、animation_name 与实际图集；映射缺失可在单位属性中手动指定。独立 PNG 序列需按原始画布对齐，编辑器无法推断已丢失的裁边偏移。

为什么不能添加飞行轨道？

先添加“播放技能特效”，再在场景或时间轴中选中它。飞行引用特效轨道实例 ID，选中左侧资源并不等于选中了场景特效实例。

为什么改了 FPS，伤害仍然在原来的时刻？

检查伤害轨道是否使用了动作帧关联。绝对毫秒时间不会跟随 FPS 改变。另请检查改的是源动作自身的 FPS，还是只改了“技能设置”的默认值；默认值只影响之后新建的动作。

为什么选了第 6 帧，预览却在最后一帧触发？

帧号指动作相对帧，不能超过实际动作帧数。超过时预览会钳制到末帧，并给出配置提示。请核对动作帧缩略图，设置一个存在的帧号；本例步兵攻击只有 5 帧。

为什么特效没飞完就消失，或者动画播完后静止？

填写非循环“持续时间”后，到时立即隐藏，即使还在飞行中。希望自然播放到到达时，可留空持续时间；非循环动画先播完时，在飞行途中保持最后一帧。需要一直播放动画则开启特效循环，结合“到达终点后隐藏特效”。

多目标打开后，为什么预览里仍只有一个特效？

“是否多目标”保存为 params.multiTarget，供战斗运行时创建特效实例时读取。当前编辑器逐条预览特效轨道，不会自动为所有受击者复制实例。

为什么强制移动没有移动到想要的格子？

确认“移动单位”选择的是正确场景实例，或“选中格子”里确实有单位。固定方向使用方向和格数；全局移动使用目标格子。检查地图边界和技能设置中的占用规则。向量模式缺少施法者或位置重合时不移动；耗时 0 为瞬移，需拖到触发前后比较。

保存显示成功，但配置仍有提示，要处理吗？

要。保存成功表示文件已写入，不代表所有资源和逻辑都满足预期。打开右侧“配置提示 → 查看全部”，逐项检查丢失资源、无效帧、伤害合计或依赖问题，再播放确认。

保存提示旧服务，或者 moveType / targetCell 丢失？

关闭旧的技能编辑器服务窗口，重新运行 SkillEditor/start.bat，再保存。当前编辑器会回读保存结果核对强制移动字段，发现丢失时显示错误并保留草稿。不要清除浏览器站点数据；先保留草稿并重启服务。

如何打开编辑器自带的“载入操作示例”？

它位于空地图中央的引导区域。若场景已有内容，可先保存当前技能，再点击“新建”创建空白技能。内置示例展示近战多段伤害、帧关联与击退，和本手册的飞行示例不同；载入会替换当前内容，支持撤销。

完成一次编排，保留一份 JSON。
